# Product Goal v2

このドキュメントは、TaskTree v2.0.0 の目標を定義します。

## 現在の位置づけ

TaskTree v1.x は、実務で学んだ技術を証明するために作成したポートフォリオプロジェクトです。

現在のプロジェクトでは、主に以下の技術を示すことを目的としています。

- Yarn Workspaces ベースの TypeScript モノレポ
- Next.js ベースのフロントエンド
- AWS Cognito 認証
- API Gateway、Lambda、DynamoDB による API
- AWS CDK によるインフラ構成
- 組織階層とロールベースのアクセス制御
- Vitest、Playwright によるテスト導入

v1.x は完成された商用アプリケーションではなく、技術証明を目的としたバージョンです。

## v2.0.0 の目標

v2.0.0 の目標は、AI エージェントチームを積極的に活用し、TaskTree を実際のアプリケーションに近い品質へ改善することです。

重点目標は以下です。

- 実際に利用できるタスク管理体験を作る。
- 会社、事業部、部署、チーム、ロールに基づく権限フローをより明確にする。
- 認証、招待、会員登録、オンボーディングの流れを安定化する。
- ダッシュボード、タスク詳細、チーム管理の UX を改善する。
- API エラー処理とデータ検証を強化する。
- テスト、ドキュメント、デプロイの流れを整理する。
- ポートフォリオとして説明可能なアーキテクチャ完成度を確保する。
- SI 会社をターゲットにした製品として、社長は会員登録時に自社を作成し、組織階層を構成できるようにする。
- 将来的な v2.0.0 改善では、依頼元企業や協力会社など複数の会社が、ひとつの案件またはプロジェクト単位に参加する構造を検討する。
- ただし、現在のデータモデルの基本組織階層は `company -> division -> department -> team -> user` を必ず維持する。
- 依頼元企業と協力会社のコミュニケーションを通じて、案件を解決していくことを長期目標とする。

## プロダクト方針

TaskTree は、単なる TODO リストではなく、組織ベースの業務管理アプリケーションを目標とします。

重要なユーザーフローは以下です。

- ユーザーが登録し、認証する。
- 会社は会員登録時に作成される。
- 事業部（division）を作成する。
- 事業部の中に部署とチームを構成する。
- 上位階層のユーザーが下位階層のユーザーを招待する。
- ロールに応じて閲覧できるタスク範囲が変わる。
- ユーザーはタスクを作成、閲覧、更新、削除する。
- 管理者は下位組織のタスクを管理する。

## 優先順位

v2.0.0 で優先するのは、機能数ではなく完成度です。

- ユーザーフローが途中で破綻してはならない。
- エラーはユーザーが理解できる形で表示する。
- 権限とデータアクセス範囲は予測可能でなければならない。
- フロントエンド、core、API、インフラの責務境界を必ず維持する。
- AI が修正しても構造が崩れないように、ドキュメントとテストを強化する。
