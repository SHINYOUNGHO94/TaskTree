## 원본 요구사항 메모 (유저 초안)

### project
- project는 최종목표이다.
- project 안건에는 의뢰처를 초대 할 수 있다.
- 의뢰처는 해당 안건의 초대로 해당 taskTree에 접속 가능하다.
- 의뢰자는 거래처탭에서 안건의 현 상황을 파악 가능하다.
- 의뢰자는 해당 안건에 자신이 요구하고 싶은 수정사항이나 개선사항이 있을시 해당 초대받은 안건의 자식안건에 추가가 가능하다.
- 의뢰자를 초대한 순산 안건 작성자는 해당 의뢰자에게 승인요청후 최종적으로 의뢰자가 승인해야 해당 proejct가 끝이난다.

### 거래처
- 거래처는 의뢰자이다.
- 의뢰자이니 안건 작성등을 해 의뢰처에게 안건을 개시 할 수 있다.
- 의뢰자의 안건은 다른색이나 표시등으로 다른 안건들과 다르게 구별되게 한다.
- 거래처탭에 의뢰자로서 초대받은 사람의 회사명이 표시되는 유저리스트를 만든다
- 거래처의 유저리스트에 거래처유저를 등록함으로서 조직구성탭에 거래처 유저는 포함시키지 않는다.

### 안건
- 안건의 내용기입란이 있는데 작은 안건은 괜찮지만 큰 안건인 경우 기입할 내용이 많을거라 생각한다, 그에 반헤 해당 내용 기입란은 가독성과 입력하는데 불편함이 많다. 이에 대해 어떻게 해야될지 조언을 구한다.
- 해당 안건에 대해 스크린샷이나 파일등이 필요한 경우가 있을거라 생각한다. 파일 업로드 기능을 포함시키며, 만약 파일이 이미지 파일인 경우 내용안에 포함시키도록 한다. 포함할때는 해당 입력커서쪽에 파일 업로드시 이미지 파일인경우 해당 이미지를 입력커서쪽에 포함시킨다. 포함시킨 이미지는 마우스로 크기를 바꿀 수 있도록 한다.
- 단순히 메모장이 아니라 안건을 처리하도록 UI를 구성하고 싶어. 이 부분에 대해서는 어떻게 해야될지 아직 못정했으니 대안을 제시해주었으면 해

### 대시보드탭
- 현재 대시보드탭은 내안건과 공개안건 조직안건 프로젝트를 선택 가능하지만 UI는 변경없이 해당 필터만 걸려서 보여지고 있다. 필터를 걸고 안건을 확인하는데 가로스크롤바를 움직여서 확인해야 된다. 이와 같은 UI는 매우 불편하다고 생각들기 떄문에 해당 [내안건],[공개안건],[조직안건],[프로젝트]의 UI버튼크기를 조금 크게 늘리고 그 밑에 안건 상태에 따른 타원형 버튼을 추가시킨다
- 타원형버튼추가로 전체 부터 시작해 각 상태인 [진행중],[검토요청]등등에 대한 버튼이 있어야 한다.
- [전체]상태가 디폴트로 전체인경우 지금의 UI구조로도 괜찮다고 생각한다.
- [진행중]등의 상태버튼을 클릭시 지금 UI가 가로막대로 대시보드가 깔려있으며 그위에 안건이 올려져 있는 상태인데 큰 네모의 하나의 대시보드로 통일하고 해당 부분에 바툭판형식으로 안건을 개시한다
- 타원형버튼은 형재 진행중인경우 파란색이며 검토요청인경우 보라색인데 해당 부분에 맞는 색으로 타원형버튼의 색을 정한다

## Task A: 대시보드 탭 UI 개선 — `feature/dashboard-status-pills`

**현황:** 탭(내안건/공개안건/조직안건/프로젝트) 선택 후 필터만 걸리고 UI 변화 없음. 보드뷰 가로 스크롤 불편.

**옵션 A-1 (Claude 권장):** 상태 pill + 보드뷰 자동 전환
- 탭 버튼 크기 확대
- 탭 아래에 상태 pill 버튼 추가: `전체` / `진행중` / `검토요청` / `완료` / `대기중` / `보류` / `취소` / `재개`
- `전체` 선택 → 현재 리스트뷰 유지 (변경 없음)
- 특정 상태 pill 선택 → 해당 상태 안건만 보여주는 보드뷰로 자동 전환
- pill 색상은 상태별 기존 색상 그대로 (진행중=파란색, 검토요청=보라색 등)
- 인프라 변경 없음. 프론트엔드만.
- ✅ 장점: 보고 싶은 상태만 집중해서 확인 가능. 가로 스크롤 문제 해소. UX 직관적.
- ❌ 단점: 특정 상태 선택 시 다른 상태 안건이 화면에서 사라짐. 전체 진행 현황 파악 불가.

**옵션 A-2:** 상태 pill + 보드뷰 컬럼 하이라이트
- pill 클릭 시 기존 전체 보드뷰로 전환 + 해당 컬럼 강조, 나머지 컬럼 흐리게
- 전체 맥락을 유지하면서 현재 상태 포커스 가능
- ✅ 장점: 전체 상태 흐름(보드 전체)을 유지하면서 현재 집중할 상태만 강조. 맥락 유지.
- ❌ 단점: 가로 스크롤 문제 완전 해소 안됨. 흐린 컬럼이 시각적으로 복잡해 보일 수 있음.

**Claude 추가 아이디어:**
- pill 옆에 해당 상태 안건 수 뱃지 표시 (예: `진행중 3`)
- 모바일: pill 가로 스크롤 (overflow-x-auto)

**→ 선택:** A-1 / A-2

## Task B: 안건 내용 편집기 개선 — `feature/case-rich-editor`

**현황:** 단순 textarea. 긴 내용 입력 시 가독성 및 조작 불편.
**확정:** 이미지 인라인 삽입 포함.

**옵션 B-1: Tiptap 리치 텍스트 에디터 + S3 이미지 업로드** (Claude 권장)
- WYSIWYG 편집 (굵기, 기울임, 목록, 제목 등)
- 커서 위치에 이미지 인라인 삽입 (드래그 리사이즈 지원)
- 이미지는 S3에 저장 → CDK에 S3 버킷 추가 필요, 새 Lambda(presigned URL 발급) 필요
- ✅ 장점: 가장 완성도 높은 편집 경험. 이미지 인라인+리사이즈 완전 지원. 실제 업무 앱 수준.
- ❌ 단점: 구현 복잡도 가장 높음. S3 + CDK + Lambda 추가로 인프라 변경 필요. 작업 시간 가장 김.

**옵션 B-2: Markdown 에디터** (`@uiw/react-md-editor` 등)
- 편집 / 미리보기 모드 전환
- 이미지 삽입: Base64로 DynamoDB 저장 (소용량 이미지만 가능, 약 400KB 이하)
- 인프라 변경 없음
- ✅ 장점: 인프라 변경 없음. 구현 빠름. 개발자 친화적. 서식(굵기/목록/코드블록 등) 지원.
- ❌ 단점: 이미지 크기 제한 엄격 (400KB 이하). 큰 스크린샷 업로드 불가. Markdown 문법 학습 필요. 이미지 리사이즈 불가.

**옵션 B-3: 자동 높이 확장 textarea** (최소 변경)
- 입력 내용에 따라 자동으로 높이 증가
- 이미지는 본문 인라인 아닌 별도 첨부 섹션에 표시
- 인프라 변경 없음
- ✅ 장점: 구현 가장 빠름 (수시간). 인프라 변경 없음. 기존 UX 유지.
- ❌ 단점: 서식 없음. 이미지 인라인 불가. 긴 안건에서 가독성 개선 폭 작음.

**Claude 추가 아이디어:**
- 단계적 접근 가능: 먼저 B-3으로 즉시 개선 → 이후 B-1으로 업그레이드
- 이미지 인라인+리사이즈 원하면 B-1 필수

**→ 선택:** B-1 / B-2 / B-3 / 단계적(B-3 → B-1)

## Task C: 안건 상세 화면 UI 구조화 — `feature/case-detail-layout`

**현황:** 모든 섹션(설명/작업/클레임/자식안건/참여회사/댓글/이력) 세로 나열. 스크롤이 길어짐.

**옵션 C-1: 2컬럼 레이아웃** (Claude 권장)
- 왼쪽 고정 패널: 상태 / 담당자 / 기한 / 스코프 / 참여회사 등 메타 정보
- 오른쪽 메인: 내용 + 작업 + 댓글 + 이력
- SI 업무 앱다운 구성. 좁은 화면에서는 왼쪽 패널 접기 버튼 제공.
- ✅ 장점: 메타 정보 항상 보이면서 내용도 동시에 확인 가능. Jira/Linear 같은 업무 앱 표준 레이아웃. 가장 전문적인 느낌.
- ❌ 단점: 모바일에서 2컬럼 대응 추가 작업 필요. 현재 상세 페이지 컴포넌트 구조 대폭 수정.

**옵션 C-2: 탭 분리**
- `개요` / `작업` / `댓글` / `이력` / `첨부파일` 탭으로 섹션 분리
- 현재 세로 스크롤 대신 탭 클릭으로 섹션 이동
- ✅ 장점: 긴 스크롤 해소. 섹션 간 이동이 명확. 모바일 대응 쉬움.
- ❌ 단점: 탭 이동할 때마다 다른 섹션 정보가 가려짐. 작업 목록 보면서 댓글 동시 확인 불가. 정보 밀도 낮아짐.

**옵션 C-3: 현재 구조 유지 + 섹션 접기/펼치기**
- 각 섹션에 접기 버튼 추가
- 필요한 섹션만 펼쳐서 확인
- ✅ 장점: 변경 최소화. 기존 구조 유지. 구현 빠름.
- ❌ 단점: 근본적인 스크롤 문제 해소 안됨. 접힌 상태가 기억 안되면 매번 펼쳐야 함.

**→ 선택:** C-1 / C-2 / C-3

## Task D: 거래처 탭 강화 — `feature/partners-client-list`

**현황:** 미수락 초대 / 협업 이력만 표시.

**옵션 D-1: 거래처 유저 리스트**
- 거래처 탭에 초대받은 회사명 + 담당자 표시
- 현재 구조상 이미 별도 companyId로 분리됨 → UI 라벨 추가만으로 해결 가능
- 조직구성 탭과 명확히 분리 (거래처 유저는 조직구성에 미포함 확인 및 명시)
- 새 API 필요: `GET /company/partners`
- ✅ 장점: 어떤 회사와 협업 중인지 한눈에 파악 가능. 구현 난이도 낮음.
- ❌ 단점: 유저 목록만 있고 실제 안건 연결 없어 활용도 낮을 수 있음.

**옵션 D-2: 거래처별 진행 안건 집계**
- 거래처 목록에 현재 협업 중인 안건 수 표시
- 거래처 클릭 → 해당 거래처와의 안건 필터 뷰로 이동
- ✅ 장점: 거래처별 업무 현황을 즉시 파악 가능. 실용성 높음.
- ❌ 단점: 거래처 목록 + 안건 집계 API 신규 필요. D-1보다 구현량 많음.

**옵션 D-3: D-1 + D-2 둘 다**
- ✅ 장점: 거래처 탭이 실질적인 B2B 협업 허브로 기능.
- ❌ 단점: 구현량 가장 많음. API 2개 이상 신규 필요.

**→ 선택:** D-1 / D-2 / D-3

**현황:** 외부 회사 = 협업자(COLLABORATOR)만 존재. 의뢰처(최종 승인자) 개념 없음.

**구현 요소:**

- 의뢰처는 거래처 탭에서 프로젝트 진행 상황 확인
- 의뢰처 안건 → 다른 색상/뱃지로 구별
- 의뢰처가 자식 안건에 수정/개선 요구사항 추가 가능 (permission 모델 변경 필요)
- 안건 작성자 → 의뢰처에게 최종 승인 요청 → 의뢰처 승인 후 PROJECT 완료
- 새 API: `PUT /cases/{id}/client-approve`

**옵션 E-1: CLIENT 타입 최소 구현** (Claude 권장 - 먼저 진행)
- `participantType` 필드 추가 + 거래처 탭 진행 상황 확인 기능만
- 의뢰처 안건 색상 구별
- 자식 안건 생성 권한 및 최종 승인은 다음 단계
- ✅ 장점: 리스크 낮음. 동작 확인 후 E-2로 확장 가능. 빠르게 의뢰처 개념 도입.
- ❌ 단점: 의뢰처가 실제로 할 수 있는 것(자식 안건 추가, 최종 승인)이 없어서 반쪽짜리 기능.

**옵션 E-2: 전체 구현**
- E-1 전체 + 자식 안건 생성 권한 + 최종 승인 API
- DynamoDB 스키마 변경 + 새 Lambda 여러 개 + permission 모델 대규모 수정
- 리스크 높음 → 반드시 별도 Task로 분리
- ✅ 장점: 의뢰처 플로우 완전 구현. 포트폴리오로서 차별화 포인트 최대.
- ❌ 단점: 구현 복잡도 v2.2 전체에서 가장 높음. 설계 실수 시 permission 모델 전체 재작업 위험.

**→ 선택:** E-1 먼저 / E-2 한번에 / 나중에

- **→ 포함 / 나중에**

### 알림 기능 (Notification)
- 상태 변경 / 새 댓글 / 클레임 승인 / 담당자 변경 시 헤더 벨 아이콘으로 알림
- 최소 구현: DynamoDB에 알림 record 저장 + 폴링 (인프라 소규모 추가)
- 고급 구현: WebSocket / Server-Sent Events (인프라 대규모)
- **→ 포함(최소) / 포함(고급) / 나중에**

### 안건 템플릿
- REQUEST용 / STANDARD용 / PROJECT용 사전 입력 구조 제공
- 자주 쓰는 안건 유형에 맞게 제목/내용/스코프 자동 채우기
- 인프라 변경 없음. 프론트엔드만.
- **→ 포함 / 나중에**

### 서버 사이드 검색 강화
- 현재 클라이언트 필터링 → 안건 수 많아지면 성능 저하
- Lambda 내 필터링 강화 또는 DynamoDB 검색 패턴 개선
- **→ 포함 / 나중에**
